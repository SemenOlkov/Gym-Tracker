# Технические и нетехнические требования к мобильному приложению-трекеру тренировок

## 1. Введение

### 1.1 Цель разработки
Разработать мобильное приложение для персонального отслеживания тренировок в тренажёрном зале. Приложение предназначено исключительно для личного использования, некоммерческое, должно помогать пользователю фиксировать результаты, анализировать прогресс и получать рекомендации по рабочим весам.

### 1.2 Целевая аудитория
Один пользователь (владелец устройства). Приложение не требует многопользовательской поддержки или облачной синхронизации (всё локально).

### 1.3 Платформа и язык разработки
- **Платформа:** Android (минимальная версия API 21 – Android 5.0, или более современная, например API 24).
- **Язык разработки:** Kotlin.
- **Среда разработки:** Android Studio.

---

## 2. Общие требования

### 2.1 Требования к функциональности
Приложение должно обеспечивать:
- Создание, редактирование и удаление тренировок.
- Добавление упражнений в тренировку с детальными параметрами (вес, повторения, подходы).
- Отслеживание собственного веса тела.
- Визуализацию прогресса в виде графиков.
- Интеллектуальные рекомендации по рабочему весу на основе истории.
- Возможность создания пользовательских упражнений с настраиваемыми атрибутами.

### 2.2 Требования к данным
- Все данные хранятся локально на устройстве (без серверной части).
- Использование реляционной базы данных (SQLite через Room).
- Автоматическое резервное копирование не требуется, но желательно предусмотреть экспорт/импорт данных (например, в JSON) для переноса на другое устройство.

### 2.3 Требования к интерфейсу
- Интуитивно понятный, минималистичный дизайн (Material Design).
- Поддержка тёмной и светлой темы (опционально).
- Адаптация под разные размеры экранов (телефоны, планшеты).

## 3. Функциональные требования (по пунктам из описания)

### 3.1 Создание тренировки
- Пользователь может создать новую тренировку, указав дату и время (по умолчанию – текущие).
- Тренировка может быть названа произвольно или автоматически (например, «Тренировка 2026-08-16»).
- Возможность редактирования названия и даты.
- Удаление тренировки с подтверждением.

### 3.2 Добавление упражнений в тренировку
- При добавлении упражнения пользователь выбирает из предустановленного списка (см. п. 3.8) или создаёт своё (см. п. 3.7).
- Для каждого упражнения указываются:
    - **Вес** (в килограммах, с точностью до 0,5 кг, если упражнение с весом; для упражнений без веса поле неактивно).
    - **Количество повторений** (целое число).
    - **Количество подходов** (целое число) – каждый подход сохраняется как отдельная сущность с возможностью отдельного редактирования веса/повторений (если пользователь хочет варьировать вес по подходам).
- При добавлении упражнения приложение должно отобразить **рекомендуемый рабочий вес** (см. п. 3.5).
- Для монолатеральных упражнений (только на одну сторону) необходимо разделять подходы для левой и правой стороны – каждая сторона фиксируется отдельно (т.е. в одном подходе указываются значения для левой и правой конечностей отдельно).
- Возможность удалять или изменять порядок упражнений в тренировке.

#### 3.2.1 Структура подходов
- Каждый подход – отдельная запись в БД, содержащая:
    - ID упражнения в тренировке.
    - Номер подхода (порядковый).
    - Вес (может быть null, если упражнение без веса).
    - Количество повторений.
    - Для монолатеральных – дополнительный вес/повторения для противоположной стороны (или отдельные поля, или отдельные записи).
- При добавлении упражнения с указанием количества подходов создаётся заданное число записей с одинаковыми весом и повторениями, но затем пользователь может отредактировать каждый подход индивидуально.

### 3.3 Добавление собственного веса
- Пользователь может фиксировать свой вес тела в любой день (не привязан к тренировке, но может быть добавлен в тренировку как дополнительная информация).
- Дата и время записи, вес в кг с точностью 0,1 кг.
- Отображение истории веса в виде графика (см. п. 3.6).

### 3.4 График прогресса в максимальных весах для каждого упражнения
- Для каждого упражнения (стандартного и пользовательского) строится график динамики максимального поднятого веса за тренировку.
- По оси X – дата тренировки, по оси Y – максимальный вес (из всех подходов в этой тренировке для данного упражнения).
- Если упражнение монолатеральное, график должен показывать отдельно максимальный вес для левой и правой стороны (или комбинированный? Лучше раздельные линии).
- Для упражнений без веса график не отображается или отображает количество повторений (максимальное за подход).
- График должен быть интерактивным (масштабирование, просмотр значений по точкам).

### 3.5 Система рекомендаций по рабочему весу
- При добавлении упражнения в тренировку приложение анализирует историю выполнения этого упражнения (все предыдущие тренировки) и предлагает рекомендуемый рабочий вес для первого подхода (или для всех подходов).
- Алгоритм рекомендации (упрощённый):
    - Найти последнюю выполненную тренировку с этим упражнением.
    - Взять вес, с которым было выполнено наибольшее количество повторений (или средний вес по подходам).
    - Если в последней тренировке количество повторений в каком-либо подходе превысило целевой диапазон (например, >12 повторений), то рекомендуется увеличить вес на шаг (например, +2.5 кг для жима лёжа, +5 кг для ног и т.д.) – шаг может быть настраиваемым для каждого упражнения.
    - Если количество повторений было слишком малым (<6), то рекомендуется уменьшить вес.
    - Для упражнений с прогрессией на уменьшение (гравитрон) – рекомендация должна уменьшать вес при росте повторений.
    - Для упражнений без веса рекомендация не выводится.
    - Для монолатеральных – рекомендация отдельно для левой и правой стороны (если данные различаются).
- Рекомендация отображается в момент добавления упражнения в тренировку (например, под названием упражнения: «Рекомендуемый вес: 90 кг»).
- Пользователь может принять рекомендацию (автоматически подставить вес) или ввести свой вес вручную.

### 3.6 График веса тела
- Отображение изменения веса тела за всё время.
- По оси X – дата, по оси Y – вес.
- Возможность просмотра в разных временных интервалах (неделя, месяц, всё время).

### 3.7 Создание собственного упражнения
- Пользователь может создать новое упражнение, задав:
    - **Название** (обязательно).
    - **Есть ли вес** (да/нет) – если нет, поля веса в подходах скрыты.
    - **Прогрессия весов** – увеличение или уменьшение (для алгоритма рекомендации). По умолчанию – увеличение.
    - **Тип** – билатеральное или монолатеральное. Если монолатеральное, то при добавлении в тренировку нужно разделять подходы для левой и правой стороны (каждая сторона имеет свои значения веса и повторений).
- Созданные упражнения сохраняются в общий список (наравне со стандартными) и доступны для выбора при добавлении в тренировку.
- Возможность редактирования и удаления пользовательских упражнений (удаление только если не используется в тренировках, иначе предупреждение).

## 4. Нефункциональные требования

### 4.1 Производительность
- Быстрый отклик интерфейса (менее 200 мс на действия).
- Плавная прокрутка длинных списков тренировок и упражнений.
- Графики должны загружаться мгновенно (оптимизация запросов к БД).

### 4.2 Надёжность
- Приложение не должно вылетать при некорректном вводе (валидация данных).
- Автосохранение при добавлении упражнений (чтобы не потерять данные при случайном закрытии).
- Целостность данных: каскадное удаление тренировок и упражнений (если удаляется упражнение, то удаляются все связанные подходы).

### 4.3 Удобство использования (Usability)
- Минимальное количество действий для добавления тренировки (быстрый старт).
- Чёткая навигация: нижнее меню или боковая панель с разделами: «Тренировки», «Упражнения», «Графики», «Вес тела», «Настройки».
- Подсказки и инструкции для новых пользователей (возможно, краткое онбординг).

### 4.4 Офлайн-режим
- Все функции работают без интернета (хранилище локальное).
- Никакие данные не передаются в сеть.

### 4.5 Безопасность
- Нет требований к аутентификации, поскольку приложение личное.
- Доступ к данным только через локальное хранилище.

### 4.6 Расширяемость
- Архитектура должна позволять легко добавлять новые упражнения, алгоритмы рекомендаций и визуализации.
- Модульность: разделение на слои (UI, ViewModel, Repository, DAO).

### 4.7 Тестируемость
- Написание модульных тестов для бизнес-логики (алгоритмы рекомендаций, работа с БД).
- UI-тесты (Espresso) для ключевых сценариев.

## 6. Алгоритмы и бизнес-логика

### 6.1 Алгоритм рекомендации рабочего веса
Входные данные: Exercise, дата текущей тренировки.
Шаги:
1. Найти все записи WorkoutExercise для этого упражнения, отсортировать по дате тренировки убыванию.
2. Взять последнюю тренировку, где упражнение выполнялось.
3. Из неё получить все подходы (Set) для данного упражнения.
4. Для билатеральных – собрать все значения weight и reps.
5. Определить «рабочий вес»: обычно это вес, с которым было выполнено наибольшее количество повторений (или вес в подходе с максимальным объемом). Упрощённо: взять средний вес по подходам (или медиану), или вес, который повторялся чаще всего.
6. Определить целевой диапазон повторений (может быть задан пользователем в настройках, по умолчанию 8-12). Если в последней тренировке максимальное количество повторений с рабочим весом больше верхней границы (12) – увеличить вес на шаг (progressionStep). Если меньше нижней границы (6) – уменьшить. Иначе оставить тот же вес.
7. Для упражнений с progressionType = DECREASE (гравитрон) – логика обратная: если повторений много, то вес нужно уменьшить (так как вес противовеса уменьшается при росте силы). Значит, при превышении верхней границы – уменьшить вес, при недоборе – увеличить.
8. Для монолатеральных – выполнить расчёт отдельно для левой и правой стороны, используя соответствующие подходы. Если одна сторона не выполнялась – рекомендация только для выполненной.
9. Результат: рекомендуемый вес (и для монолатеральных – два значения).

Если данных нет – рекомендация не выводится (или предлагается начальный вес 0).

### 6.2 График максимальных весов
Для каждого упражнения и каждой тренировки вычисляется максимальный вес среди всех подходов (для билатеральных – просто max weight; для монолатеральных – отдельно max для левой и правой стороны). Строятся точки (дата, maxWeight). График отображается по выбору упражнения.

### 6.3 График веса тела
Точки (дата, weight) из таблицы BodyWeight, отсортированные по дате.

## 7. UI/UX требования

### 7.1 Основные экраны
- **Главный экран (список тренировок)** – отображает все тренировки, сгруппированные по месяцам. Кнопка «Новая тренировка».
- **Экран создания/редактирования тренировки** – позволяет выбрать дату, добавить упражнения (кнопка «Добавить упражнение»). Список уже добавленных упражнений с возможностью редактирования каждого подхода (по нажатию на упражнение открывается экран с подходами).
- **Экран добавления упражнения** – список всех доступных упражнений (стандартные + пользовательские). При выборе отображается рекомендуемый вес (если есть) и поля для ввода веса, повторений, количества подходов. Для монолатеральных – отдельные поля для левой и правой стороны (или две колонки).
- **Экран подходов** – список подходов с возможностью редактировать вес и повторения для каждого подхода. Для монолатеральных – два поля на подход.
- **Экран графиков** – выбор упражнения для просмотра графика максимальных весов; также отдельный график веса тела.
- **Экран управления упражнениями** – список всех упражнений, кнопка «Создать своё». Возможность редактирования/удаления пользовательских.
- **Экран веса тела** – добавление новой записи веса, отображение списка записей и графика (или график вынесен в отдельный раздел).

### 7.2 Навигация
- Использовать нижнюю навигационную панель с четырьмя вкладками: «Тренировки», «Упражнения», «Графики», «Вес тела» (или «Профиль»).
- Вкладка «Настройки» (шестерёнка) – доступ к настройкам приложения (целевые диапазоны повторений, единицы измерения, тема и т.п.).

### 7.3 Взаимодействие
- При добавлении упражнения в тренировку после выбора из списка открывается диалог или экран с параметрами.
- Подходы создаются автоматически, но пользователь может их редактировать (добавлять/удалять подходы).
- Возможность копировать тренировку (повторить предыдущую) – полезно для быстрого создания однотипных тренировок.
- Удаление тренировки – через долгое нажатие или кнопку «Удалить».

### 7.4 Визуальные требования
- Использовать Material Design компоненты (CardView, RecyclerView, FloatingActionButton).
- Графики – использовать библиотеку MPAndroidChart или аналогичную.
- Чёткое отображение единиц измерения (кг, повторения).
- Для монолатеральных упражнений – визуально разделять данные на лево/право (например, цветами или иконками).

## 8. Технические требования к реализации

### 8.1 Стек технологий
- **Язык:** Kotlin.
- **UI:** XML-разметки, Material Design, ViewBinding.
- **Архитектура:** MVVM (Model-View-ViewModel) с использованием LiveData или Flow, Room для БД, Coroutines для асинхронности.
- **База данных:** Room (SQLite) – сущности, DAO, миграции.
- **Графики:** библиотека MPAndroidChart или AnyChart для Android.
- **Внедрение зависимостей:** Dagger/Hilt или Koin (для простоты можно обойтись без DI, но для тестируемости рекомендуется).
- **Тестирование:** JUnit, Mockito, Espresso.

### 8.2 Структура проекта (пакеты)
- `data` – модели данных, DAO, база данных.
- `domain` – бизнес-логика, use cases (алгоритмы рекомендаций, вычисление максимумов).
- `ui` – Activity/Fragments, ViewModels, адаптеры.
- `utils` – утилиты (форматеры дат, константы).

### 8.3 Хранение данных
- Room БД с миграциями (при изменении схемы).
- Начальные данные (стандартные упражнения) загружаются при первом запуске (или встроены в БД через предзаполнение).

### 8.4 Обработка ошибок
- Валидация ввода: вес > 0, повторения > 0, дата корректна.
- Сообщения об ошибках через Toast или Snackbar.
- Обработка исключений при работе с БД (логгирование в Logcat).

### 8.5 Фоновые задачи
- Все операции с БД выполняются в фоновом потоке (Coroutines) без блокировки UI.
- Расчёт рекомендаций – лёгкий, может выполняться на главном потоке, но лучше вынести в фоновый.

## 9. Ограничения и допущения

- Приложение разрабатывается для одного пользователя, поэтому нет синхронизации и многопользовательского доступа.
- Данные хранятся только локально; при удалении приложения данные теряются (нет облачного бэкапа).
- В качестве единицы измерения веса используется килограмм (кг), повторения – целые числа.
- Точность веса – 0.5 кг для штанги/гантелей, но можно вводить с точностью 0.1 кг (гибкость).
- Рекомендации по весу основаны на простой эвристике; в будущем можно усовершенствовать.
- Предустановленные упражнения нельзя удалить, но можно редактировать их параметры (кроме названия)? Лучше сделать их только для выбора, но можно разрешить изменение шага прогрессии.
- При монолатеральных упражнениях количество подходов задаётся общее, но подходы дублируются для каждой стороны (т.е. если 3 подхода, то будет 6 записей в БД: 3 левые, 3 правые). При отображении можно группировать.
